Why it matters

        
Everyone has questions. Few people know SQL.

        

          Company data lives in databases, and getting an answer usually means
          writing code. The Copilot removes that wall, and shows you the SQL so
          you grow your skills as you go.
        

        

          

            
Anyone can ask

            

              A sales manager, a student or an analyst can ask “Which country
              buys the most?” and get a table and a chart.
            

          

          

            
Learn SQL by seeing it

            

              Every answer comes with its SQL. Read it, edit it, run it again,
              and watch what changes.
            

          

          

            
Safe by default

            

              Queries are checked first and run by a read-only user, so nothing
              can be deleted or changed.
            

          

        

        
Project at a glance

Safety and quality

        
Safe by design: the AI can read, never change

        

          

            1
            
SQL validator

            

              Only one read-only SELECT is allowed. INSERT, UPDATE, DELETE, DROP
              and similar commands are blocked.
            

          

          

            2
            
Read-only user

            

              The database account the app uses has permission to read, and
              nothing else.
            

          

          

            3
            
Limits

            

              A read-only transaction, a 10 second timeout and a 1000 row limit
              stop heavy or risky queries.

Under the hood

        
Built with popular, industry-standard tools

Run it yourself

        
Run it on your own computer (Windows)

        

          You need Python 3.10+, Node.js LTS, PostgreSQL with the northwind
          database, and a Groq API key.
        

        
    
          
  1. 
            Database users and tables
            
    psql -U postgres -d northwind -f database\01_readonly_user.sql
psql -U postgres -c "CREATE DATABASE myapp_db;"
psql -U postgres -d myapp_db -f database\02_history_table.sql
    
          
    2. 
          
  2. 
            Settings: create backend/.env (never share it)
            
    GROQ_API_KEY=your-groq-api-key
GROQ_MODEL=openai/gpt-oss-120b
SAMPLE_DB_URL=postgresql://copilot_ro:password@localhost:5432/northwind
APP_DB_URL=postgresql://postgres:password@localhost:5432/myapp_db
AUTH_SECRET=a-long-random-secret
    
          
    3. 
          
  3. 
            Backend
            
    cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
    
          
    4. 
          
  4. 
            Frontend (second terminal)
            
    cd frontend
npm install
npm run dev
    
            Then open http://localhost:5173.
          
    5. 
        

        
Test it

        
cd backend
.\.venv\Scripts\Activate.ps1
python tests\test_validator.py
python tests\run_eval.py
cd ..\frontend
npm run build

        

          test_validator.py checks the safety rules. run_eval.py asks the 30
          test questions and saves details to backend/tests/eval_results.json.
          It needs the databases, a Groq key and the backend settings.
        

        
Questions students ask

        

          Can it delete or change my data?
          

            No. Queries are checked, then run by a read-only user inside a
            read-only transaction.
          

        

        

          What if the AI writes a wrong query?
          

            If the database returns an error, the error is sent back to the AI
            for one retry. You can also edit the SQL yourself and run it again.
          

        

        

          Why choose only some tables?
          

            A smaller schema means a shorter prompt, so the AI stays focused and
            makes fewer mistakes.
          

        

        
If something goes wrong

        

          “python is not recognized”
          

            Install Python again and tick “Add Python to PATH” during
            installation.
          

        

        

          PowerShell blocks the virtual environment
          

            Run
            Set-ExecutionPolicy -Scope CurrentUser RemoteSigned,
            then activate .venv again.
          

        

        

          The page says the API is offline
          

            Check that the backend terminal is running
            uvicorn app.main:app --reload --port 8000.
          

        

        

          Database connection failed
          

            Make sure the PostgreSQL service is running, the northwind database
            exists, and the usernames and passwords in .env are
            right. SAMPLE_DB_URL must point to the sample database
            and APP_DB_URL to the app database.
          

        

        

          Groq authentication error
          

            Check GROQ_API_KEY in backend/.env, then
            restart the backend.
          

        

        

          The table list is empty
          

            The backend must connect to SAMPLE_DB_URL and the
            database user must be able to read the schema information.
          

        

        
Security notes

        
    
          
  • 
            Never share .env files, API keys, database
            passwords or AUTH_SECRET.
          
    • 
          
  • 
            Use a long, unique AUTH_SECRET outside local
            development.
          
    • 
          
  • Keep the sample database user read-only.
    • 
          
  • Do not expose PostgreSQL directly to the internet.
    • 
          
  • 
            Keep the SQL validator and read-only runner switched on in
            production.
